## 青蛙跳（荷塘跳跃）玩法设计 v0.1
- 产出 `docs/青蛙跳玩法设计.md`：第 6 种玩法 `frog` 的完整设计，仅设计未实现。
- 核心机制：青蛙四态机 蓄力(0.55s，末 0.35s 落点亮光圈) → 腾空(0.75s，唯一 +2 窗口"空中截击") → 落水(0.28s) → 静坐(0.90s)，循环约 2.5s，换荷叶再蓄力。
- 阶段参数：同屏 3→4→5；蓄力 0.60/0.52/0.44；静坐 1.00/0.80/0.62；阶段③ 连环跳最多 3 连。难度/连击/自适应倍率沿用现有链路。
- 差异化定位：现有玩法区分在"目标怎么动"，青蛙补「低频大位移 + 可预判抛物线」，比蝴蝶慢、比爬虫有爆点。
- 技术映射：config.js 加 TYPES/TYPE_BGS.frog/FROG_PARAMS；scenery.js 加 buildPond（6 片荷叶）；prey.js 加 Frog 类；game.js onHit 加 isFrog(+2 → bonusHits)；audio.js 三个合成音。预计 400-500 行，不动现有玩法。
- 待用户确认：模式名、+2 是否保留、阶段③ 3 连是否过难、是否首版带"飞虫抢食"副玩法。

## 核查：好友排行数据可达性
- 链路现状：主域 `reportBest()` 用 `wx.setUserCloudStorage({key:"bestHits"})` 写入；开放数据域 `openDataContext/index.js` 用 `wx.getFriendCloudStorage({keyList:["bestHits"]})` 读 + 渲染，key 一致，`game.json` 已声明 openDataContext。链路是通的。
- **缺口**：官方文档明确 `wx.getFriendCloudStorage` 需要用户授权 `scope.WxFriendInteraction`，项目里从未请求过；未授权/已拒绝时直接 fail，代码里 fail → `cache=[]` → 显示“好友里还没有成绩”（会误导成“没人玩”）。
- 其他前置条件：对方也玩过并写入过 bestHits；新加微信好友 2 小时内可能拿不到（官方说明）；开发者工具/体验版基本空榜（无真实关系链）；后台《用户隐私保护指引》需声明朋友信息。
- 数据边界：只能拿同玩好友的 openid / nickName / avatarUrl / 自己的 KVDataList，主域不可直接读好友数据（必须经开放数据域）。
- 待办（未实施）：主域在用户点击“好友排行”时 `wx.authorize({scope:"scope.WxFriendInteraction"})`，区分「未授权 / 加载中 / 好友无成绩」三态，拒绝授权给一键 openSetting 引导；注意 sharecard 的经验——不要无脑先 authorize，要带 fail 兜底。

## 修 ENOENT：assets/sfx/frog-croak-2.wav（开发者工具编译报错）
- 现象：开发者工具编译报 `ENOENT ... assets/sfx/frog-croak-2.wav [1.06.2209190][darwin-arm64] 编译报错`。
- 排查结论：**代码零引用**（全项目 grep `.wav` 只有 tools/*.py，且脚本写到 tempfile）；`assets/sfx` 里只有 4 个 mp3。
  全量搜索项目、`~/Library/Caches/微信开发者工具`、`~/Library/Application Support/微信开发者工具` 都没有该字符串/文件。
  根因推断：14:11-14:17 之间 cut_frog_voice.py 曾在 assets/sfx 下短暂写过 wav 再删，开发者工具一直开着，
  文件索引留着旧条目 → 编译时按旧索引读文件 → ENOENT。属于工具侧缓存，不是项目引用。
- 处置：① 音频重新按"最保守规格"生成（44.1kHz / 单声道 / 64kbps CBR / 无任何 ID3 标签，头部是 FFFB 同步字），
  顺手排除解码器对 32kHz+ID3v2.4 的兼容性疑虑；② `touch assets/sfx` 刷新目录 mtime 触发重新索引；
  ③ 让用户「工具 → 清除缓存 → 全部清除」或关掉项目重开。
- `tools/cut_frog_voice.py` 的输出参数已更新（-ar 44100、-map_metadata -1、-write_id3v1 0、-id3v2_version 0），
  以后重新切音频不会再出现带 ID3 的 32kHz 变体。
- 校验：ffprobe 显示 4 个文件均为 mp3/44100/1ch/64k，ffmpeg 全解码通过；check_frog_voice.js、shot_frog.js、healthcheck 全绿。
- 经验：**不要把中间 wav 写进 assets/**（工具会记进索引，删了以后编译报 ENOENT）；生成脚本一律写 tempfile 再转码。

## ENOENT frog-croak-2.wav（第二次，上传阶段仍失败）
- 复现面扩大：第一次是"编译报错"，这次是"上传失败"，同一路径 → 说明不是一次性内存状态，而是工具持有的文件索引。
- 第二轮排查：`mdfind` 全盘 + Spotlight 内容索引 + 项目内 `.DS_Store` 全部无果；磁盘上确实只有 mp3，没有 wav。
- **排除"mp3 转码"假设**：项目里 `assets/audio/` 还有 9 个 mp3（猫叫/投喂音），从没报过同名 wav —— 所以不是通用的 mp3→wav 转码，
  只有 `frog-croak-2.wav` 这一个曾经存在过 6 分钟（14:11–14:17 切音频时短暂落盘后删除）的路径被记住了。
- 处置（两条腿）：
  1. **让 wav 真的存在**：`tools/cut_frog_voice.py` 改为输出 22.05kHz/16bit 单声道 wav（4 段共 60KB），
     `js/audio.js` 的路径全部改 `.wav`；同时脚本仍输出一份 mp3 兼容副本，避免工具索引里另一批旧名字再炸。
  2. 让用户清一次工具缓存 / 关掉项目重开（索引里其它已删文件以后还可能冒出来）。
- 校验：`file` 显示 4 个 wav 都是 RIFF PCM 16bit mono 22050Hz；`check_frog_voice.js` 新增"真解码"断言
  （new Audio → loadedmetadata，时长 0.32/0.33/0.34/0.37s 全部 >0），播放链路、限流、静音全通过；
  shot_frog、healthcheck 全绿。包内音频从 13KB 变成 84KB（wav+mp3 并存），仍可忽略。
- 经验：**开发者工具的文件索引会记住"曾经存在过的路径"**，删过的资源（哪怕只存在几分钟）在编译/上传时仍会被读；
  一旦遇到这种 ENOENT，要么把该路径重新造出来，要么彻底清缓存重开项目。生成素材时不要往包目录写中间文件。
