## 大屏（平板）横屏 hero 场景图猫头被裁掉 — 修复水平裁剪锚点
- 现象：大屏（平板 S>1.35）横屏下场景图只露出猫嘴、没有猫脸；手机横屏正常。截图证据 `clipboard-2026-11-20T06-41-54-351Z-a2b33f24.jpg`。
- 根因：`js/ui.js:999` 水平裁剪锚 `sx = fx*iw - vw/2` 把**裁剪窗水平中心**锁在蝴蝶（fx=.693，图片 69.3% 处）。大屏 hero 容器 `sBoxW` 撑到 ~570vp、高 ~317vp，宽高比 1.798≈图片原始 1.779 → cover 时水平几乎整图铺满（vw≈1400, sx≈0），蝴蝶被锁在画面 69% 偏右，左侧 30%（猫头/猫脸）被挤出画面。手机横屏容器窄（~390×376, 比例1.04）水平裁中间、左右各留一部分，故小屏没事。
- 改动（仅一行，`js/ui.js:1003`）：水平锚点从蝴蝶中心 `fx*iw` 改锁「蝴蝶+猫头」主体中心 `(fx+.09)*iw`（≈.39）。猫头回到画面里、蝴蝶仍完整保留；手机横屏此锚点同样安全（水平裁中间），不影响小屏。
- 注意：`HERO_SCENE.fx` 仍保留原值 .693（蝴蝶真实位置），锚点偏移在 sx 计算处局部加 .09，不污染全局常量。
- 待用户大屏（平板横屏）目视确认猫头是否完整入画；若偏左/偏右微调 `.09` 这个偏移量即可。

## 续：锚点 .39 左移过头 → 猫头又被裁，最终锁「猫头中心 .36」
- 现象：上次改 `.09`（锚点 .393）后用户反馈"猫咪几乎看不见了"（截图 `clipboard-2026-11-20T06-44-31-610Z-736e934d.jpg`），只剩左边缘一条猫头。

## 广告改造第二版：改成「通用浮卡」——只遮挡、绝不挤压

## 修复：点广告自带的关闭键后，浮卡会自己弹回来
- 现象（已用 harness 复现）：`onClose` 只做了 `shown=false` + 清 `G.adPage`，但页面每帧都在调 `ad.pageFrame()`，下一帧 `frames` 继续累加就再次 `ad.reveal()` → `inst.show()`，广告重新出现；900ms 兜底 timer 也会补一刀。实测关闭后 120ms 内 show 次数从 1 变 2。
- 修法（`js/ad.js`）：
  - 新增模块级 `closed` 标记；`enter()` 时重置为 false（新的一次进页允许重新加载）。
  - `onClose` → `closed = true` 并**立即 `ad.leave("closed-by-user")`**（只置 shown 不够，必须销毁实例）。
  - `pageFrame()` / `reveal()` / `resume()` 全部加 `closed` 短路，堵住"帧回调 + 兜底 timer + 切后台回前台"三条重弹路径。
  - `leave()` 里对 `closed-by-user` 跳过 `hide()`（组件已被系统收起，再 hide 没意义），只 `destroy()`。
  - `state()` 暴露 `closed`，排障能一眼看出是不是用户关的。
- 新增回归 `test/probe_ad_close.js`（12 项）：竖屏首页 + 横屏召唤各验一遍——关闭后 `page/shown/frames` 归零、`closed=true`、实例 destroyed、等 1.6s（含一次 `__wxShow` 模拟回前台）不再 show 也不再新建、页面热区照旧。
- 既定行为（非 bug）：关闭只对"本次进页"生效，切到别的页再回来会重新加载一次。若要做"关闭后 N 秒 / 本次启动内不再出"，在 `enter()` 里加时间戳或 Set 即可。
- 截图：`screenshots/广告浮卡_关闭后首页.png`（关闭后页面与从未有广告时逐像素一致——浮卡只是盖在上面）。
