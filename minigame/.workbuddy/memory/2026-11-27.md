## 抖音小游戏上架调研（微信小游戏 → 抖音小游戏）

产出：`docs/抖音小游戏上架流程与适配清单.md`（完整流程 + 资料清单 + 本项目适配清单 + 官方文档索引）

### 核实过的官方口径（developer.open-douyin.com）
- 主体认证：个人=身份证+手机号/银行实名（~1工作日，可建50个小游戏，仅广告变现）；企业=营业执照+对公验证（~3工作日，100个，可开内购）。**主体类型审核后不可改**
- 软著：所有游戏必填；平台支持电子软著准入但**不支持用于小游戏备案**（备案须国家版权局登记证书）；著作权人须与主体完全一致；同一软著只能对应一款在线游戏；游戏名须与软著名一致
- 自审自查报告：自 7/11 起改为后台勾选确认，不用上传
- 版号：仅开通内购 / 已有版号时需要
- **备案顺序不可颠倒**：小游戏备案（无版号，平台代申报，需先过基础信息+版本提审）→ ICP 备案（所有类型）→ 发布
- ICP 备案：平台审核 1–3 工作日 + 管局 1–3 周 + 工信部短信核验；**提交后不可撤回**
- 提审：上传时预检，**未接 `tt.navigateToScene`（侧边栏复访，必接）直接上传失败**；2026-04-20 起提审自动上线至所有已接入宿主，QA 默认多端回归
- 包体：不分包 20MB；分包后整体 20MB、单主包 ≤4MB、单子包 ≤20MB；开放数据域 ≤4MB
- 迁移工具：IDE 内置「搬家」+ npm 包 `wx-to-tt`（`wx2tt -i <src> -o <dst>`），日志在输出目录 `__wxToTT/report/index.html`

## 首页好友排行榜 + 猎手分算法（11-27 下午）

**背景**：原有 `openDataContext` 排行榜是死代码——`openModal("lb")` 无任何入口调用，`askFriendAuth` 从未触发，`bestHits` 按裸捕获数排名（时长/玩法/难度全不归一，比的是设置不是本事）。

**设计（js/rank.js）**：`猎手分 = round(min(HPM,60) × 玩法系数 × 难度系数 × 完赛系数)`
- HPM =有效命中/实际分钟；<30s 不计；HPM 封顶 60；中途结束 ×0.85
- 玩法系数按猎物 speed/√area 推导+对数压缩：butterfly .65 / mouse .85 / fish .90 / frog .95 / tadpole 1.40 / laser 1.60 / pool 1.60
- 难度 easy/normal/hard = 1.0/1.15/1.3；榜单取近 30 天最高单局分（滚动窗口）
- **关键坑**：关系链 KV 存了 4 个字段（rankScore/rankTs/rankMode/rankDiff），ODC 必须同时读 `rankTs` 做 30 天过期判断；旧 `bestHits` 量纲不同，不再混排

**代码落点**：新增 `js/rank.js`；`game.js` 装配+endGame 写分+openModal('lb') 同手势授权；`platform.js reportRank()`；`openDataContext/index.js` 全量重写读新 KV；`js/ui.js` 底栏第 5 格「好友排行」（trophy 图标）+ 窄屏 5 格改图标上/文字下竖排（横排必撞字）。

**测试**：新增 `test/probe_friend_rank.js`（13/13 算法单测）、`test/probe_friend_rank_entry.js`（入口/授权/ODC/结算 KV 8/8）。**新增模块时必须同步给所有 35 个 test/*.js 的 MODS 数组注入 `./js/rank.js`**，否则 harness 迷你 CommonJS 找不到模块、全探针挂掉。截图 `screenshots/首页_好友排行入口_{横屏,竖屏,矮横屏}.png`、`好友排行弹窗_入口.png`。

## 调研：小游戏能否做「用户自设定时提醒 → 推送微信」
- **结论**：技术上只能做「一次性订阅 + 服务端定时下发」，做不到长期自动推送。项目当前纯前端、零服务端，要落地必须先搭后端。
- 官方事实（2026-04 文档）：
  - 小游戏支持 `wx.requestSubscribeMessage`（tmplIds，一次最多 5 个模板，须在点击行为里调）与服务端 `subscribeMessage.send`（必须在服务端调，支持云调用）。消息落微信「服务通知」。
  - **一次性订阅**：订阅成功 1 次 = 下发 1 条额度，可累加；「总是保持以上选择」只是不弹窗，不产生额度，额度用完报 43101 → 必须再调订阅接口续额度。
  - **小游戏唯一的长期/永久订阅是系统订阅消息**（`wx.requestSubscribeSystemMessage`，订阅 1 次永久有效、平台下发多条），但只有 3 种固定场景：好友互动提醒、排行榜超越提醒、游戏更新提醒，**内容和触发逻辑平台定死**，不能拿来自定义用户提醒。
  - 小程序侧的「长期订阅 / 长期限频订阅（每日/每月）」只对政务民生、医疗、交通、金融、教育等公共服务开放，**游戏类目拿不到**。
  - 发送接口无「定时发送」参数——到点推送靠自己的服务端定时任务扫描 trigger。
- 落地链路：前端设时间 + `requestSubscribeMessage` 拿授权 → 传 openid 和提醒时间存后端 → 定时触发器到点调 `subscribeMessage.send`。需在 MP 后台申请订阅消息模板 ID；用户 openid 需 `wx.login` 换。

## 实现：好友超越提醒（关系链系统订阅消息，**零服务端**）
- 官方事实：该类消息是「平台下发消息 + 平台设置内容」，`wx.requestSubscribeSystemMessage({msgTypeList:["SYS_MSG_TYPE_RANK"]})` 订阅 1 次永久有效、可下发多条；本周期有战绩且已订阅时，好友超越即推服务通知，**当天首次被超越发 1 条**。前端 `wx.setUserCloudStorage` 上报即可，后台接口 `storage.setUserStorage` 才需 access_token/签名。
- **关键坑**：MP 后台「微信排行榜配置」只影响搜索/社交组件/服务通知，**不影响**现有主域+ODC 自绘的游戏内榜单。必须额外上报标准 key `hunterScore`，value = `JSON.stringify({wxgame:{score,update_time}})`，`update_time` **必须秒级**（毫秒会失效），`wxgame` 下不能加自定义字段。MP 配置需先提交版本审核+运营素材才看得到入口，且需微信审核通过。
- 改动：`js/platform.js` 加 `reportOfficialRank` / `rankNoticeState`（`getSetting({withSubscriptions:true})` 读 `subscriptionsSetting.itemSettings.SYS_MSG_TYPE_RANK`）/ `subscribeRankNotice`；`js/rank.js` 在 `updateRankBest` 刷新最高分时额外写标准 KV；`game.js` 加 `rankNoticeState` 状态机（定义后再调用，赋值表达式不提升）；`js/ui.js` 已授权时把底部主按钮拆两枚，右枚「开启超越提醒」，已订阅则变灰「已开启超越提醒」——不新增行，避免横屏把榜单挤到 <90px。
- 验证：`test/probe_rank_notice.js` 11/11（冷启动状态、标准 KV 秒级时间戳、按钮注册、点击调 API、同意/拒绝/不支持降级、老玩家识别），harness 补 `requestSubscribeSystemMessage` 与 `subscriptionsSetting` 垫片；截图 `screenshots/好友排行_超越提醒按钮_{横屏,竖屏}.png`、`好友排行_超越提醒已开启.png`。全量探针回归仅剩 2 个历史遗留失败（countdown 调不存在的 API、tadpole 坐标未乘 S）。

## 授权弹窗收口（用户选：合并入口、保留真名）
- **事实**：好友信息(`wx.authorize`)、真名(`wx.createUserInfoButton` 原生按钮，`wx.authorize` 对它无效)、超越提醒(`wx.requestSubscribeSystemMessage` 订阅面板)属于三套独立机制，**微信没有合并授权 API**；`wx.openSetting` 只显示已请求过的权限，首次无法一次开完。能做的只是「一个入口」，弹窗仍按顺序弹。
- 实现：`game.js` 去掉打开榜单自动 `askFriendAuth`，改为 `platform.friendAuthSilent()` 静默 `getSetting` 回读（ok/denied/unknown），不弹窗；新增 `G.enableLbFeatures()` 在同一次 touchEnd 里同步触发好友授权（或拒绝态去 openSetting）+ 提醒订阅，并置 `G.nickStepReady=true` 才放出原生真名按钮。关弹窗重置。
- `js/ui.js`：底部恢复单按钮，文案随状态变「开启好友榜 / 开启完整好友榜 / 下一步：授权真名 / 开启超越提醒 / 邀猫友比一比」；真名提示行未点入口时显示「先点下方按钮，再在这里授权真名」，点后显示「点这里授权真名（好友可见）」。注意 unknown 态别写「正在请求好友权限…」，那是 asking 态文案。
- 探针同步更新：`probe_friend_rank_entry.js`（进榜不再自动弹、点合并入口才授权、静默进榜、拒绝态）、`probe_nick_auth.js`（先点合并入口才创建原生按钮）、`probe_rank_notice.js`（只有合并入口、重复点不重复订阅）。截图 `screenshots/授权合并_{未开启,待开启,待开启_竖屏,已点入口}.png`。
- 复用坑：`game.js` 里都是赋值表达式（非函数声明），**调用必须写在定义之后**，否则冷启动静默回读会静默失效。

## 修复「排行榜自己那行显示'我'」（第五轮，用户真机反馈）
- **根因**：`displayList()` 补自己那行时硬编码 `nickName: selfName || "我"`；而 ODC 的 `wx.getUserInfo` 在真机常退化成匿名/空，`getUserCloudStorage` 又常返回空 → selfName 为空 → 显示"我"+占位头像。主域原生按钮虽拿到了真昵称头像，但只写了 KV，没保存也没传给 ODC。
- 修复链路（真资料优先，本地缓存兜底）：
  - `game.js`：新增 `G.myProfile` + `G.saveMyProfile()`，授权成功时把 `info.nickName/avatarUrl` 存本地 `myWxProfile`（wx.setStorageSync）；`checkNickAuth` 在已授权但无缓存时用主域 `wx.getUserInfo` 补齐；授权回调改为调 `G.ui.showLB()`，一次重发 refresh+show 把资料带进 ODC。
  - `js/ui.js` `ui.showLB()`：show 消息的 self 附带 `name/avatar`。
  - `openDataContext/index.js`：`applySelfFromMain()` 接收 name/avatar 并置 pinned 标记（关系链/KV/getUserInfo 的异步结果不能回覆盖真资料；无分数时也让资料落地）；`displayList()` 去掉"我"兜底；渲染时自己那行（含好友榜内 openid 命中的行）强制用 selfName/selfAvatar。
