## 青蛙跳模式：青蛙视觉尺寸偏大（用户「检查一下青蛙跳模式，青蛙好像有点大了」）
- 检查方法：`/tmp/cat-green/shot_frog.js` 用 harness 进 frog 局（localStorage 写 targetType=frog，
  `G.startGame()` → 等 4.6s 倒计时 → playing），三视口截图并读 `G.preys[0].sc / baseW / G.scene.pads[].r` 量化。
- **实测改前**：1080×608（虚拟 765×430，S=1.412）青蛙视觉盒 126×102、荷叶宽 158 → 占 80%；
  852×393 视觉 106×87、荷叶仅 97 → **青蛙比荷叶还宽**，完全盖住叶子，不像「蹲在荷叶上」。
- **根因**：`js/prey.js` 渲染分支视觉系数写死 0.85，但 `applySize()` 的 `sc` 还叠了
  `DIFF.easy.size=1.3`（默认难度已改 easy）和 `big = 1+(S-1)*0.45`（大屏 1.185），
  `sc` 实际 1.30~1.54，0.85 并没把体型压回设计值。`config.js` 里 frog 命中盒仍是 96×78（不算大）。
- **修复（只改 `js/prey.js` 的 frog 渲染分支）**：
  ① 视觉系数 0.85 → 0.72；② 加自适应上限 `visS = min(sc*vs*0.72*shareScale*(1-drownK*.34),
  荷叶平均直径*0.80/96)`，读 `G.scene.pads[].r` 求均值，任何屏幕都保证荷叶四周露一圈；
  ③ 水面投影与发光半径改用同一个 `visS`，不再用 `sc`，避免影子/光晕比青蛙大太多。
  **命中盒 `baseW*sc` 完全不动**，逗猫的宽容判定不变（注释里原本就刻意让视觉 < 命中盒）。
- **改后实测**：1080 → 107×87（占荷叶 68%）；852 → 80×65（80%）；竖屏 390×844 → 81×66（80%）。
  三视口 `hitW/hitH` 与改前一致（148×120 / 125×102 / 125×101），`G.onHit` 拍中 hits 0→1 全通过，零报错。
- 回归：verify.js 11 用例、verify_pages.js 9 组、verify_final.js 五视口几何断言 ALL PASS。
  备份 `/tmp/cat-green/bak/prey-before-frog.js`，对照图 `/tmp/cat-green/青蛙尺寸对照.png`，
  最终截图 `shots/final-frog-{1080,852,port}.png`。
- **经验**：猎物/角色的视觉尺寸不要只靠固定系数，要与场景锚点（荷叶、洞口）按比例挂钩；

## 场景选择页选卡交互优化（用户发截图「游戏选这卡交互需要优化一下」）
- **发现的真 bug**：绘制层是循环画廊（j=-2..n+1 取模，第一张时左右都显示邻卡），
  但 `G.bgPickArrow` 用 `Math.max/min` 钳制 idx → **第一张点左侧卡（鱼群巡游）完全没反应**，
  看得见点不动。另外侧卡没有场景名、指示点只是画着不能点、切换反馈弱。
- **修复（game.js + ui.js）**：
  ① 新增 `P.visIdx` 连续索引（可 <0 或 ≥n），`P.idx = mod(visIdx, n)` 仍是真实索引；
     `bgPickArrow` 改为按 visIdx ±1 循环，`relOff = (ni-visIdx)*step` 让邻卡从正确方向滑入；
     `bgPickTouchStart` 把 visIdx 规范化回 idx，拖动仍保留首尾阻尼（手感不变）。
  ② 新增 `G.bgPickJump(i)`：指示点可点，走环形最短路径（`delta>n/2` 则减 n），动画同箭头。
  ③ ui.js 绘制全部改用 visIdx（j 循环、dotPos 取模、说明文案 cur、cards fallback）。
  ④ 侧卡显示场景名（白底小标签，左卡贴右缘/右卡贴左缘，避开被裁掉的半边）+ 淡 chevron 提示可点。
  ⑤ `P.selT0` 驱动切换瞬间 220ms 的 1.035 弹性回弹；`btn(dx-18,dotY-18,36,36)` 扩大指示点命中区。
