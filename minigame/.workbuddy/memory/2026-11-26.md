## 加载页进度条值域修复：归一到 0~100（13:50）

用户报：加载页进度条数据不是 1-100。

### 根因
- `wx.loadSubpackage.onProgressUpdate` 的 `res.progress` **值域跨平台不一致**：文档/模拟器 0~100，**iOS 真机（基础库 2.1.x）实测返回 0~1**（微信官方社区已确认的兼容性坑）。
- 原代码直接 `G.assetsProgress = res.progress` 当百分比用 → 真机 0.5 显示成 "1%"、进度条几乎不动。

### 修复
- `game.js` 新增 `G.normSubpackageProgress(res)`：优先用字节比 `totalBytesWritten/totalBytesExpectedToWrite×100`（两端都是 0~1 的权威比例，消歧义）；分母为 0 / 字节数缺失时按 progress 值域兜底（≤1 视为 0~1 乘 100，>1 原样）；夹到 0~100；负数/NaN/null 返回 null 跳过。
- 回调改为 `v = norm...; if (v > G.assetsProgress) G.assetsProgress = v` —— **单调不回退**，回调乱序/重复推旧值不让进度条倒跳。

### 验证
- 新增 `test/probe_loading_progress.js`：14 项全绿——字节比权威（iOS 0.5 / 模拟器 50 都得 50%）、无字节兜底（0.5→50、50→50、1→100）、越界夹取、非法值跳过、单调性、绘制路径不报错、无页面异常。
- 回归：probe_ad_placements / probe_mouse_sfx 全绿、probe_tadpole 36/36。
- 注意：devtools 环境走 `platform==="devtools"` 放行分支，不进加载屏，看不到进度条；此修复针对真机。改动仍未提交。
