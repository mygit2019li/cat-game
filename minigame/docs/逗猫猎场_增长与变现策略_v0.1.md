# 逗猫猎场 · 增长与变现策略 v0.1

> 前置：本稿基于《逗猫猎场_PRD》V1.0、《规则优化建议 v0.1》与当前代码基线。
> 新增输入（本次确认）：① 吸引猫玩；② 解决主人没时间陪；③ 可持续地玩；④ 主人愿意晒结果与**过程视频**；⑤ 变现靠固定位广告 / 激励视频。
> 所有金额、留存、eCPM 均标注为**假设**，需真实数据替换。

---

## 0. 结论先行（三个判断）

**判断一：这不是「游戏」，是「托管型玩具」。**
目标用户是「没时间的主人」，意味着**任何需要主人点击才能继续的环节都是漏斗漏洞**。当前核心循环是「结算 → 点再来一局 → 再结算」，而主人此刻在忙——3 分钟一到，屏幕停在结算页，猫走开，产品在这一天就结束了。这是当前最大的规则缺口，比评级不准严重得多。

**判断二：分享的主角是「视频」，不是「评级卡」。**
现在的分享卡是一张静态图，带评级与截图（`js/sharecard.js`）。但「晒猫」的内容逻辑是「看我猫多可爱/多蠢」，不是「看我猫 hpm 18」。而且——**代码里没有任何录屏能力**（已核实：无 `getGameRecorderManager`）。要「愿意晒过程视频」，规则层必须先产出「值得剪的 15 秒」：高光事件必须被定义、被标记、被记录。

**判断三：广告只能是「主人价值链」的交换，不能是「猫的成绩」的交换。**
局内放广告 = 猫拍广告 = 无效曝光 + 主人反感 + 猫被中断。激励视频若做成「复活/加时/双倍分」，猫无法理解，评级可信度也直接垮掉。唯一成立的交换是：**主人用一次广告，换更好的素材或更多新鲜感**。

## 1. 四个目标翻译成指标（以及它们的三处冲突）

| 目标 | 可验证指标 | 当前状态 |
|---|---|---|
| 吸引猫玩 | 局内「有效扑击时长占比」= 有 touch 的秒数 / 总秒数 ≥ 55%（假设） | 无该指标；只有 touches 计数 |
| 解决主人没时间 | 单次会话「无人值守时长」中位数 ≥ 12 分钟（假设） | 硬上限 = 一局时长（最长 5 分钟），之后等人点 |
| 可持续玩 | 周活跃主人 ≥ 1.5 天/周；猫的「新鲜感衰减」被内容轮换抵消 | 无轮换机制，同一玩法重复 |
| 愿意晒 | 周分享率 ≥ 8%（假设），其中**视频**占分享 ≥ 50% | 只有图片分享卡；无视频 |
| 变现 | 人均激励视频展示 ≥ 1.2 次/日（假设）；ARPDAU 0.1–0.2 元（假设） | 无广告 SDK 接入 |

**三处冲突（必须显式取舍）：**

1. **自动续局 ↔ 广告展示**：猫需要连续玩，广告需要主人看到。→ 解法：广告只在「主人回到前台」时出现，结算数据挂起等他回来（见 §3.2）。
2. **锁内容 ↔ 分享意愿**：把新玩法锁在激励视频后，免费用户只有 2 种玩法 → 素材单调、晒的意愿下降。→ 解法：**六种核心玩法永久免费**，只把「场景皮肤 / 稀有猎物 / 视频导出」放在广告后。
3. **局内零广告 ↔ 收入**：局内是猫的领域，放广告等于污染产品核心。→ 解法：全部收入来自**局外**（首页/结算/记录）与**主人主动动作**，接受较低的库存密度，用留存和分享换规模。

## 2. 规则重构：从「一局游戏」改成「一次陪伴会话」

### 2.1 会话（Session）成为新的规则单位

现在的单位是「局」（60/180/300s）。目标用户需要的是「**一段被托管的时间**」——主人去忙 20 分钟，回来看到猫玩了 6 局、有 3 个高光片段。

```
新概念：会话 = 连续若干局，直到猫离场或被主人结束
会话内：局 → 3s 过渡 → 下一局（自动，无需主人点击）
        过渡时自动轮换：玩法 / 场景 / 海域 各按「今日排期」换
猫离场：idle 25s → 本局结束 → 进入「待机页」（不动画面、不耗电、屏幕可常亮变暗）
        猫回来（任意触摸）→ 3s 倒计时 → 继续下一局
主人回来：看到「本次会话：6 局 / 42 分钟 / 3 个高光」，再决定 晒 / 继续 / 结束
```

**规则参数（假设）：**

| 项 | 值 | 理由 |
|---|---|---|
| 单局时长（会话内） | 60s | 短局 = 更多次「开局新鲜感」，也更适合剪视频 |
| 局间过渡 | 3s（含倒计时） | 与现有开局一致，不新增体感 |
| 自动续局上限 | 8 局 / 会话（可关） | 防止猫过度兴奋，也给出自然的「主人回来」节点 |
| 待机触发 | idle 12s 降速，25s 结束本局，40s 进待机页 | 三档渐进，避免误判趴着休息 |
| 待机唤醒 | 任意触摸，无需点击特定区域 | 猫爪落哪都算 |

> **为什么短局更好**：长局对猫是「一段持续的强度」，短局是「一串小高潮」。后者既符合猫的 burst 行为，也让「每局一个高光片段」成为稳定产出——这直接服务分享与广告。

### 2.2 高光事件（规则层定义，供录屏打点）

「愿意晒视频」的前提是视频里有东西可看。建议定义 6 类高光，局内实时打点（时间戳 + 类型）：

| 高光类型 | 触发条件 | 录屏价值 |
|---|---|---|
| 空中截击 | 青蛙腾空命中 | 高（画面动感强） |
| 连击爆发 | combo ≥ 5 / ≥ 10 | 高（特效最亮） |
| 稀有目标 | 金色鱼 / 大帝王蝶等里程碑目标命中 | 高（视觉独特） |
| 双爪乱拍 | 300ms 内 ≥ 2 个不同触点 | **极高**（这是「猫真的在玩」的证据） |
| 惊飞瞬间 | 蝴蝶 STARTLED / 老鼠受惊 | 中（可爱） |
| 长时间专注 | 连续 20s 无失误且有命中 | 中（证明「这款玩具能留住猫」） |

**「双爪乱拍」是最值钱的一类**：主人晒的不是游戏特效，是猫的失控。规则层只需按触点时间戳聚类，成本极低，但决定了视频的传播力。

录屏实现建议：`wx.getGameRecorderManager()` 常开（缓冲最近 30s），命中高光时打时间戳；结算页提供「自动剪 15s」→ `shareVideoMessage` 分享（需用户手势触发）。

### 2.3 评级降级为主人附注，不再是主角

v0.1 建议里我花了不少篇幅修评级可比性。按新目标，优先级要**下调**：评级对猫无意义，对主人的价值也只在「一句可引用的话」。

```
保留：评级（作为结算页一行小字 + 分享文案的形容词）
下调：hpm 归一化 → 从 P0 降为 P2
上调：会话统计（局数/总时长/高光数/双爪次数）→ 成为结算页主视觉
```

### 2.4 内容轮换（解决「可持续」）

猫的新鲜感衰减来自「同一画面重复」。会话内已自动换玩法/场景；跨天再叠一层：

```
今日排期：每天 0 点按日期种子生成 —— 默认玩法、海域、稀有目标概率
「今日三景」：一天内前 3 局自动切换三种玩法，第 4 局起回到猫最常玩的那种
主人视角：结算页显示「今天猫玩了 3 种场景」，给出「明天换新场景」的期待
```

**注意**：轮换是「视觉与新意」的轮换，不是「难度」的轮换——难度仍由 §v0.1 的滑窗自适应控制，两套机制不要互相干扰。

## 3. 变现设计

### 3.1 三个广告位（全部在局外）

| 位置 | 形式 | 触发 | 频控 | 备注 |
|---|---|---|---|---|
| 首页底部条 | 固定 banner | 常驻 | — | 低对比度、避开「开始」按钮 200px；猫在首页时勿用高饱和动图（会引爪误点） |
| 结算页 | 固定 banner（**下方 1/4**） | 常驻 | — | 上方留给统计与分享按钮；**不要盖在主视觉上**，否则分享截图自带广告 |
| 会话总结页 | 插屏 | 主人主动「结束会话」 | 1 次/3 分钟，≤3 次/日 | 只有主人明确结束才弹，猫已离场，风险最低 |

**明确不做：**
- 局内任何广告（含激励）
- 倒计时 / 结算动画中弹插屏
- 首页全屏插屏（猫在开机瞬间会看到，误点率高、投诉风险高）

### 3.2 激励视频：五个「主人换东西」的场景

核心原则：**只卖素材与新鲜感，不卖成绩。**

| # | 激励点 | 主人得到 | 猫得到 | 价值判断 |
|---|---|---|---|---|
| 1 | **导出无水印视频** | 可晒、可发朋友圈 | — | **最高价值**：直接服务「愿意晒」，且是主人主动点 |
| 2 | 高清/长版分享卡皮肤 | 更好看的图 | — | 次高，制作成本低 |
| 3 | 解锁 24h 新场景/新海域 | 猫不容易腻 | 视觉新鲜感 | 支撑「可持续」，且可复用现有素材 |
| 4 | 本周记录扩容 7 天 → 30 天 | 「成长回顾」 | — | 培养长期关系，为「月度视频合集」铺路 |
| 5 | 电子猫粮自动出粮延长 | 省事 | 有粮 | 与陪伴定位天然契合 |

**频控**：每日激励 ≤ 8 次；同一激励点间隔 ≥ 30 分钟；视频导出单独放宽（这是核心价值，且频次天然有限）。

**「待领取」机制（解决冲突 1）**：会话结束但主人不在前台时，结算数据挂起；主人切回前台 → 先展示「本次会话摘要 + 3 个高光」，广告位此时才加载。避免「广告在主人不在时被展示」的无效库存。

### 3.3 收入粗算（全部为假设）

假设 eCPM：激励视频 60 元、banner 10 元、插屏 40 元。

| 场景 | DAU | 激励视频/人/日 | Banner 曝光/人/日 | 日收入 | 月收入 |
|---|---|---|---|---|---|
| 早期 | 1,000 | 1.2 | 6 | 1.2×60/1000 + 6×10/1000 → 132 元 | ≈ 4,000 元 |
| 成长 | 5,000 | 1.5 | 6 | 450 + 300 = 750 元 | ≈ 22,500 元 |
| 规模 | 20,000 | 1.8 | 6 | 2,160 + 1,200 = 3,360 元 | ≈ 100,000 元 |

**这个模型说明什么：** 广告是「保底现金流」，不是「增长引擎」。要到月入 10 万量级，需要 DAU 2 万——靠买量买不来（宠物类小游戏 CPI 假设 3–8 元，LTV 远不够）。**唯一的可持续路径是分享带来的自然量**，也就是为什么 §2.2 的高光视频比多塞一个广告位重要一个数量级。

**三条可叠加的第二曲线（建议 v2.0 评估）：**
1. **垂直广告主**：猫粮/猫砂/猫抓板品牌。同一 eCPM 下转化率高 3–5 倍（假设），且与产品调性一致，不伤体验。
2. **电商分佣**：视频/分享卡里挂「同款逗猫玩具」或猫粮链接，按成交分佣。
3. **品牌联名场景**：把某个场景（如「猫粮品牌主题海域」）做成限时内容，收品牌方费用——比 banner 高一个量级，且是内容而非广告。

## 4. 如果只做三件事（按投入产出排序）

| 顺序 | 动作 | 解决的矛盾 | 改动面 |
|---|---|---|---|
| **1** | **自动续局 + 待机页** | 主人没时间 → 单次会话从 3 分钟变 20–40 分钟；广告库存与素材量同比例放大 | `game.js` 结算分支 + 主循环；无需新素材 |
| **2** | **高光打点 + 30s 缓冲录屏 + 一键晒视频** | 愿意晒 → 拉新闭环 | `wx.getGameRecorderManager`、`shareVideoMessage`；规则层加高光定义 |
| **3** | **局外三个广告位 + 激励「无水印导出」** | 变现 | 接流量主 SDK；结算页与导流文案 |

第 1 项是**一切的前提**：没有自动续局，会话时长被硬截断，后面的素材量、广告库存、分享机会全部按 3 分钟封顶。

## 5. 指标与验证

| 层级 | 指标 | 目标（假设） | 验证方式 |
|---|---|---|---|
| 北极星 | 周人均「有效扑击时长」（分钟） | ≥ 25 分钟/周 | 局内 tick 聚合 |
| 猫 | 局内有效扑击占比 | ≥ 55% | 同上 |
| 猫 | 会话长度中位数 | ≥ 4 局 | session_start/end |
| 主人 | 会话回看率（主人打开结算的比例） | ≥ 60% | 前台回调 |
| 主人 | 周分享率（含视频） | ≥ 8%，视频占比 ≥ 50% | share_tap + shareVideo |
| 变现 | 激励视频/人/日、ARPDAU | 1.2 次、0.15 元 | 广告 SDK 回调 |
| 留存 | 次留 / 7 留 | 35% / 15% | 平台后台 |

**必须新增的埋点**：`session_start` / `session_end`（局数、时长、高光数）、`idle_enter/resume`、`highlight`（type, ts, combo）、`ad_show`（pos, kind, filled）、`video_export`（是否分享、时长）、`settle_view`（主人是否回看）。

## 6. 与 v0.1 规则建议的合并（优先级调整）

| v0.1 条目 | 新优先级 | 原因 |
|---|---|---|
| 计分「+2」倒挂 → 分值恒为 1 | **P1**（原 P0） | 仍要改（否则评级与「双爪/hpm」统计失真），但不阻塞增长主线 |
| idle / 离场规则 | **P0 升级** | 从「体验补丁」升级为「会话机制的地基」 |
| 自适应 ↔ 连击解耦 | **P1**（原 P0） | 影响体感但不影响留存主链路 |
| 评级归一（baseline） | **P2 下调** | 评级不再承担主要反馈职责 |
| 节奏脉冲化（55s 周期） | **P1 升级** | 与「短局 + 自动续局」天然同构，可直接吸收为「局内脉冲」 |
| 首局脚本 | **P1** | 首因效应仍重要，但改为「首个会话脚本」：30 秒内必命中一次 + 自动续局演示 |
| 判定保底 22px | **P1** | 影响「猫是否打得中」= 影响留存 |
| 猫档案驱动难度 | **P2** | 有价值，但次于会话机制 |

## 7. 风险与红线

| 风险 | 说明 | 应对 |
|---|---|---|
| 猫对广告画面产生抓挠 | 首页 banner 若高对比/动画，会被猫当猎物 | banner 用低饱和静态图；避开主视区 |
| 自动续局导致「猫过度兴奋」 | 连续 8 局可能过长 | 上限 8 局 + 强制休息（每 3 局插入 20s 安静段） |
| 录屏内存/时长限制 | 不同机型缓冲能力不同 | 常开 30s 缓冲，超限降级为「仅高光 15s」 |
| 分享视频需用户手势 | 不能自动弹 | 结算页主按钮「晒猫视频」，点击即分享 |
| 流量主开通门槛 | 需满足平台既有要求（以现行规则为准） | 先把留存与分享做起来，攒量再开通 |
| 广告与未成年人/宠物安全 | 需在隐私与适龄提示中说明 | 局内零广告已是最强保护 |

## 8. 待你拍板

1. **会话单位是否成立**：接受「一次打开 = 一段被托管的陪伴（多局）」而不是「一局」？这决定后续所有规则重写范围。
2. **单局降到 60s**：短局更利于分享与新鲜感，但主人看「战绩」时数字不那么壮观（会有 6 局 300 分）。是否接受用「会话总览」替代「单局战绩」作为主视觉？
3. **核心玩法是否永久免费**：我建议是（只锁场景与素材），若你希望锁玩法，需要重新评估分享意愿的损失。
4. **视频导出是否作为主要激励点**：这会决定是否把录屏能力排在广告 SDK 之前做。
