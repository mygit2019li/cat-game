# 逗猫猎场 · 规则优化建议 v0.1

> 评审对象：《逗猫猎场_PRD》V1.0（2026-11-15）+ 当前代码基线（`game.js` / `js/config.js` / `js/prey.js`）
> 目的：在 MVP 已跑通「六玩法 + 六规则系统」的前提下，修正规则层面的**激励错位、调控冲突、闭环缺失**，不新增玩法。
> 说明：文中标注「（假设）」的数值为待校准的初值，需用真实埋点回归后替换；其余数值均来自当前代码。

---

## 0. 结论摘要

1. **得分体系存在倒挂**：静止/停留状态命中给 +2（`game.js:602 / 589`），移动目标只给 1 分，等于奖励「最省力」的一次扑击，同时把 `hpm` 抬得不可比。
2. **两个难度调控器在最需要时同时失灵**：自适应辅助的开关是 `combo < 3`（`game.js:504`），而连击提速在 `missStreak ≥ 3` 时被强制归零（`game.js:527`）。猫连续拍空 → 辅助不生效、提速却清零，两个方向都往难走。
3. **评级只看 `hpm`，跨玩法/跨数量不可比**：`hpm ≥ 18` 即「捕猎大师」（`game.js:491`），但单只 fish 的理论天花板约 12–14（假设），而 7 光点 laser、10 洞捕鼠可轻松 30+。评级失去了「反馈」功能，只剩随机性。
4. **缺少猫离场规则**：全局无 idle 检测（已核对：`game.js` 无 idle/lastTouch 相关逻辑）。猫走开后 3 分钟计时照跑，屏幕常亮、记录 0 命中、污染 hpm 基线，还会给出「慵懒观察员」这种对主人无信息量的结论。
5. **长局没有节奏起伏**：阶段划分固定 `20s / +50s / 其余`（`config.js:672`），3 分钟局有 110s 恒定停在阶段③，无限模式永远停在阶段③。与 PRD 自述的「节奏有起伏」相悖。

## 1. 评审口径：这个产品的真实指标

PRD 2.3 写「围绕『猫愿意玩多久』设计」，但规则系统的评价对象全部是**人的游戏框架**（连击、评级、难度档、分数）。猫的真实行为只有三个可观测信号：

| 信号 | 含义 | 当前是否被使用 |
|---|---|---|
| 主动扑击次数与间隔 | 猫是否还在玩 | 被记成 `touches`，但只用于算命中率，不参与难度与结算判断 |
| 命中率 | 目标是否「打得中」 | 仅展示，不参与评级 |
| 离场/回头 | 是否该结束或该休息 | **完全没有** |

建议把产品指标改成：
- **北极星（假设）**：单次会话「有效扑击时长」——有 touch 的秒数 / 局时长 ≥ 55%。
- **支撑**：首局 10s 内首次命中率 ≥ 80%；idle 占比 ≤ 20%；再来一局率；7 日复玩。
- **反向**：辅助 3 级触发占比、tier 抖动次数/分钟、idle 触发率、结算跳过率。

## 3. 优化提案

### P0-1 把「难度」和「分数」分开（改 `onHit`）

现状：命中即 `S.hits++`，高难窗口额外 `S.bonusHits++`，两者都进 `hpm`。

建议规则：

```
命中：hits += 1                    // 只记「抓到一次」，恒为 1
高难窗口（腾空/窜洞/变向中）：
    combo += 2                     // 连击双倍，给爽感
    特效升级 + 专属音           // 反馈加强
    不增加 hits，不进 hpm
停留/静止窗口：
    不再 +2，改为「下一个目标刷新更快 0.3s」  // 奖励节奏，不奖励分数
```

- `hpm` 只由 `hits` 计算 → 跨玩法、跨数量可比，评级才有意义。
- 「+2」的爽感通过 `combo` 双倍与特效保留，猫感知不到数字，主人感知的是评级是否可信。
- 影响面：`game.js:450 / 476 / 491 / 596-609`。改动小，收益最大。

### P0-2 评级改「相对本猫基线」而非绝对 hpm

```
baseline(mode, difficulty, preyCount)   // 首次用表打底，之后随猫档案滚动
score_norm = hpm / baseline
评级：≥1.60 捕猎大师 / ≥1.15 矫健猎手 / ≥0.75 灵巧学徒 / else 慵懒观察员
```

打底表（**均为假设值，需埋点回归修正**）：

| 玩法 | fish | butterfly | mouse | laser | pool | frog |
|---|---|---|---|---|---|---|
| baseline hpm（标准/单只） | 12 | 13 | 14 | 20 | 10 | 16 |

修正系数（假设）：多只 ×1.8、hard ×1.35、easy ×0.8、1 分钟 ×0.95（热身占比高）。

- 首次启动无历史 → 用打底表；`archive`（`config.js` 已有 `hpmBase / hpmRecent`）一旦有 3 局即切到「本猫基线 ×1.15 = 大师」。
- 附带解决「多只必大师」和「单只永远学徒」两个极端。

### P0-3 新增猫离场规则（idle）

```
idleSec：距上次 touch 的秒数（暂停/倒计时不计）
idleSec ≥ 12s → 等待态：目标速度 ×0.7、音量 -40%、四周暗角 + "轻触唤醒"文案
                （不计入 hpm 分母，避免稀释）
idleSec ≥ 25s → 自动结束本局：done=0, reason=idle
                结算文案改为「这一局猫没来玩」，不评级、不生成分享卡
任意 touch → 立即回到对局，idleSec 清零
```

- 对主人：不再收到「慵懒观察员」这种错误结论；对开发：`done=0` 的原因可分流（manual / idle / crash）。
- 顺带解决屏幕常亮耗电。
- 影响面：`game.js` 主循环 + 结算分支（`endGame`）+ 埋点。

### P0-4 自适应与连击解耦 + 渐变（改 `applyAdaptive` / `applyComboBoost`）

现状三处硬伤：开关看 `combo`、提速被 `missStreak` 一刀切归零、强度无平滑。

建议：

```
窗口：最近 20 秒（滑动）
hitRate = hits20 / max(touches20, 1)
进入辅助：hitRate < 0.25 且 touches20 ≥ 3
退出辅助：hitRate > 0.45 且连续 8s        // 迟滞，避免抖动
辅助强度 k = clamp(1 + (0.25 - hitRate) * 2.4, 1, 1.55)
          每秒最多变化 4%（渐变，不跳变）
连击提速不再归零：speed = combo_tier_speed * (1 - 0.5 * (k - 1))
                          限幅 [0.85, 1]   // 只回退一半，保留一点挑战
优先级：辅助 > 提速（保证「最需要帮助时一定是帮」）
```

- 关键变化：**失误阈值从「次数」改为「时间窗内的命中率」**，快爪/慢爪猫得到同等待遇。
- `COMBO_TIERS`（`config.js:594`）数值可保留，只改叠加方式。

### P1-1 长局与无限模式的节奏曲线

现状：`stageNow` 固定 `20s / +50s / 其余`，3 分钟局阶段③长达 110s。

建议改为「脉冲式」结构（不新增玩法，只改强度包络）：

```
一个周期 55s = 推进 40s + 回落 15s
推进段：当前阶段参数
回落段：速度 ×0.75、同屏数量 -1、环境变暗、音效减弱  // 不是变简单，是「歇一口」
3 分钟局：3 个周期；5 分钟：5 个；无限：周期循环
无限模式每 3 个周期插入一次 20s「完全安静段」（无目标，仅有环境音）
```

- 依据：猫的狩猎是 burst-pause 模式，20–40s 一个峰；恒定高强度反而加速弃玩。
- 回落段不该被算作「降难度」而触发辅助逻辑，两套系统要保持独立。

### P1-2 局内高潮里程碑

每 20–25s（与回合周期对齐）触发一次稀有目标：金色鱼 / 大帝王蝶 / 三连光点 / 金色青蛙，持续 3–4 秒。
命中不额外计分（保持 P0-1 的中性分值），只给最强特效 + 专属音 + `combo +3`。
作用：给 3 分钟局提供时间维度上的「值得再拍一次」的理由。

### P1-3 首局脚本（冷启动）

```
首次启动：强制 60s + 悠闲 + 自适应开（设置项置灰，第二局起解锁）
第 1 个目标：慢速（×0.6）、大体型（×1.4）、出生在屏幕中央偏下（猫自然落爪区）
前 3 次命中：反馈时长 ×1.5、音量 +3dB、额外光爆
达成点：10s 内首次命中 → 弹一次「它上手了」
```

PRD 3.3 写的「猫 10 秒内至少抓到一次」目前是**期望**而不是**保证**，需要这条脚本把它变成设计约束。

### P1-4 判定与感知一致（改 `prey` 命中盒）

```
命中半径 = max(1.15 × 可见包围盒, 可见包围盒 + 22px)   // 保底，小目标受益最大
出生保护：spawn 后 180ms 内触碰不计 miss（免疫不惩罚）
透明度不一致：把「低于阈值不可命中」改成「低于阈值不显示」  // 猫看不到就不该存在
「附近」重定义：dist ≤ 2.5 × 目标宽（替代固定 140px）
```

### P1-5 多只模式的公平与可得

- HUD 显示**实际**同屏数量，别让「7 只」名不副实（洞口/荷叶封顶要提前算）。
- 得分分母做 `√n` 折算（或直接在 baseline 里 ×1.8 吸收），避免数量堆分数。
- 目标分散度：所有多只玩法都加最小间距（参考 laser 的 150px），按屏宽 18% 计。

### P2 中长期（不阻塞发版）

| 项 | 说明 |
|---|---|
| 猫档案驱动难度 | `archive.hpmBase / hpmRecent` 已有，可直接做「开局建议难度」，替代固定三档 |
| 合并难度与辅助 | 「悠闲/标准/激烈」+「自适应」语义重叠 → 改为「自动（按猫档案）/ 手动」 |
| 结算给一条下一步 | 「今天命中率 62%，下次试试泳池追鱼」比评级更能拉动再来一局 |
| 分享卡说猫的语言 | 不用 hpm，用「抓了 12 条鱼 · 最高连击 8 · 全速追了 2 次」 |

## 4. 埋点补充（MVP 阶段最该补的一件事）

当前 13 个事件只能算「开局率/完成率」，无法验证任何规则调优。建议补：

| 事件 | 字段 | 用途 |
|---|---|---|
| `tick_agg`（每 15s 一条） | hits, touches, missStreak, adaptiveTier, comboTier, preyAlive, stage | 验证节奏曲线、辅助触发是否合理 |
| `idle` | kind(enter/resume/end), sec | 验证离场规则阈值 |
| `stage_enter` | stage, sec | 验证阶段时长与疲劳 |
| `game_end` 增补 | reason(timeout/idle/manual), bonus, maxCombo, hitRate | 评级归一与 baseline 回归 |
| `touch_gap` | 相邻 touch 间隔的分桶直方图 | 校准失误「时间窗」阈值（替代拍数） |

## 6. 风险与反向指标

| 风险 | 表现 | 应对 |
|---|---|---|
| baseline 表拍错 | 评级反而更不稳定 | 先按「本猫基线」跑，打底表只用于前 3 局 |
| 脉冲回落被猫读成「玩具坏了」 | 回落段 touch 骤降 | 回落段保留 1 个目标，只降速不消失 |
| idle 规则误伤「慢热的猫」 | 落地 12s 就进等待态 | 12s 只降速不结束；25s 才结束，且第二局起放宽到 40s |
| 取消 +2 后爽感下降 | 主人觉得「没以前热闹」 | 用 combo 双倍 + 特效升级补偿，并在结算页把 bonus 换成标签 |

## 7. 待确认（需要你拍板）

1. 产品目标是「猫玩得久」还是「主人愿意晒」？两者的评级设计取舍不同（前者重参与度，后者重可比性）。
2. 是否接受**取消 +2**（改为 combo 双倍）？这是改动最小、收益最大的一条，但会改结算页的「奖励命中 ×N」标签。
3. idle 自动结束是否需要主人二次确认（避免猫只是趴着休息就结束一局）。
4. 首局强制 1 分钟 / 悠闲，是否接受把设置项在首局置灰。
